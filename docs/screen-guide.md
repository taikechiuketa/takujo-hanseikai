# 卓上反省会 画面説明

[仕様書](specification.md)・[今回の適用内容とロールバック](ui-port-20261116.md)

## ログイン・マイグループ

通常の入口からログイン・マイグループへ進みます。メールで登録・ログインし、卓を作成・選択してください。アカウントの確認が必要な場合は確認メールから有効にします。各卓の「対局を入力」で保存済みの対局を自動取得します。取得に失敗した場合はサンプルや空の履歴へ置き換えず、エラーを表示します。

ローカル試用は `index.html?local=1` で明示的に開きます。クラウドの卓とは別の端末内データです。

## 卓の4画面

| メニュー | 内容 |
| --- | --- |
| 入力 | 対局日・伝票番号・参加者・倍率・半荘スコア・チップ・精算・保存・終了 |
| 成績 | 保存済みセットの通算成績、レーティング、個人成績、各種推移 |
| 履歴 | セットの検索・詳細・編集・削除・共有、雀簿データ取り込み |
| 設定 | プレイヤーマスター、データ管理、復旧コピー、卓の設定ページへのリンク |

「マイグループ」で卓を切り替えます。上部にログイン状態と「この端末からログアウト」を表示します。保存中・未保存・保存失敗・再試行は既存の状態表示で確認できます。ログアウト時は未送信入力を確認・保護し、この端末の認証だけを終了します。

## 対局入力

「新しいセット」で開始し、「プレイヤーを選ぶ」で参加者を選びます。登録・編集は設定のプレイヤーマスターから行えます。倍率を変える場合は「ポイント倍率・チップレート」を開きます。

「日付・番号を編集」で対局日と1以上の連番を変更できます。同じ日付・連番は指定できません。過去セットも「履歴 → 編集」から変更できます。変更後は「セットを保存」で確定します。点数・参加者・チップ・セットの内部IDは維持され、発行済みのセット共有リンクもそのまま利用できます。日付による期間別成績と日付・番号によるRの計算順には変更後の値を使います。

半荘ごとに三麻・四人三麻・四麻を選び、整数のポイントを入力します。必要人数より1人少ないところまで入力して残りの空欄を選ぶと合計0の値を補完します。抜け番は長押しで設定・解除します。

スコア表は内部スクロールです。上の対局者名と左の半荘番号、下の累計ptを固定します。「半荘を追加」で表の中だけ末尾へ移動します。

「セットを保存」は入力を続けながらDBへ保存、「セットを終了」は精算を確認して保存し進行中セットを閉じます。チップは最後に増減枚数を入力します。マイナスは赤字、合計が0でない場合は保存時に確認します。保存失敗時も入力は端末に保持し、「保存を再試行」で確認・再送します。

## 成績・履歴

通算成績の集計期間は通算成績タブの中で選びます。個人成績、種目別成績、対戦相手別成績、ポイント・チップ・収支の推移を確認できます。標準集計は保存済みセットだけが対象です。

レーティングの現在R・対象半荘数・直近の増減は全期間です。通算成績の期間とは連動しません。表の下の「R推移の表示期間」は推移だけに適用されます。レーティング表から開く個人成績も全期間を表示します。

履歴で各セットを開くと、精算と「このセットの着順回数・割合」を確認できます。各人の有効半荘数と1〜4着の回数・割合を表示します。抜け・未入力は除外し、同点は同順位。三麻のみの参加者の4着は「—」です。「半荘別スコア」も対局者名を固定した内部スクロールで閲覧できます。

履歴の編集内容は端末に保護します。中断した場合は設定の「保護した履歴入力を再開」から確認できます。元の履歴が変更されている場合は自動復元せず、復旧コピーで内容を確認します。

## 卓の設定・データ管理・復旧

設定から「卓名・配色・ルール・共有設定を開く」で既存の卓設定へ進みます。テーマと独立したヘッダー色、ロゴ、ルール本文、点数表、公開項目を設定できます。配色のプレビュー・保存、ルールの書式入力は従来どおりです。画像・PDFは卓とアカウント別に端末保存されます。

「JSON保存／読込」は現在のセットだけ、「全データをバックアップ／バックアップから復元」は入力中セット・履歴・マスターを扱います。従来の全データ復元は確認後にDBへ保存する操作です。

新しい「復旧コピー」は、このアカウント・卓の改修前・DB取得時・送信前などのコピーを扱います。「復旧コピーを書き出す」でファイルに保存できます。「コピーの一覧を表示」で日時とセット数を確認し、「選んだコピーを端末に戻す」で復元します。この復元ではDBへ自動送信しません。確認して必要な場合だけ保存してください。

復旧コピーは端末内にあり、ブラウザデータの消去や端末故障では失われ得ます。ファイルへの書き出しも利用してください。復旧用データを保護できない場合は該当操作を止めます。

## 共有

セット共有は履歴の「共有リンク」で発行・再コピー・無効化できます。公開セットには精算・着順回数と割合・名前固定の半荘スコアを表示します。URLは内部セットIDに結び付くため、日付や番号を訂正しても維持します。

卓全体のランキング共有は卓の設定で公開項目を選びます。共有された項目だけを表示します。公開ランキングでも通算の月とレーティングを区別し、現在Rは全期間、R推移は別の期間で表示します。レート推移が非公開なら推移の操作自体を表示しません。

ランキング非表示の選手をマスターから削除した場合の保護など、共有用マイグレーションの適用条件は仕様書を参照してください。

## 運営者向け利用状況

既存の `usage.html` から登録・対局・継続状況とユーザー別の利用実績を確認できます。今回のUI移植では運営者向けの権限や集計を変更していません。

### プレイヤー登録・選択

プレイヤーのチェックは、新しい名前を登録しても保持する。追加画面で登録した人は自動的に選択される。ボタンの人数を確認して「選択した人を追加」でセットへ反映する。選択がゼロなら追加ボタンは無効。参加中の人は重複追加できない。保存中で登録できない場合は理由と再試行方法を表示し、入力した名前を保持する。

## 参加募集・チャット・プッシュ通知

マイグループの各卓の「参加募集・通知」、対局画面上部の同名リンク、または公開ランキングの「参加募集・チャット・通知」から開きます。管理者は先に卓の設定の「ランキングページの共有」をオンにしてください。仲間はその閲覧共有リンクから、ログインせずに利用できます。

「＋ 募集する」で日時・場所・麻雀の種類・決まっている人数・追加募集人数・補足を登録します。場所は「いつもの場所」が初期値で自由入力です。ほかの人は「参加する名前」を入力して参加できます。募集者は内容の編集・締切・再開・削除ができ、参加者は自分の参加を取り消せます。募集詳細には、その募集専用のチャットがあります。

通知は次のように届きます。

| 通知 | 対象 |
| --- | --- |
| 新しい募集 | 同じ卓で募集通知をONにした端末（投稿端末を除く） |
| 新着チャット | その募集のチャット通知をONにした端末（投稿端末を除く） |
| 参加・参加取消・満員 | 募集者の通知ONの端末 |

「通知設定・ガイド」で「募集通知をONにする」→通知を許可→「テスト通知を送る」の順に確認します。iPhone／iPadはiOS／iPadOS 16.4以降で、Safariの共有メニューからホーム画面へ追加し、追加したアイコンから開いて設定してください。Androidは対応するChromeなどで通知を許可します。端末別の手順と届かないときの確認事項もアプリ内にあります。

「この卓の通知をOFF」は、その卓だけの通知を停止します。複数の卓を利用している場合は、募集ページ上部で、以前に開いた卓を切り替えられます。管理者はaccount.htmlからアプリをインストールすると、マイグループが起動します。仲間は募集画面から追加してください。初回起動時に卓が未選択なら、受け取った閲覧共有リンクまたは募集リンクを「共有リンクから卓を開く」に貼り付けます。ログインは不要です。ページ内では以前に開いた卓を切り替えられます。通知をタップしても、入力途中の対局画面は別の募集画面に置き換えません。

募集・チャットの名前は自由入力で、端末の識別情報で自分の募集・投稿・参加を判定します。同名は本人確認にはなりません。ブラウザのデータを消したり別端末へ移ったりすると、自分の募集の編集・削除や参加取消を引き継げません。

募集・通知は閲覧共有リンクに結び付きます。共有をオフにすると、そのリンクでの募集・チャット利用と通知送信も停止します（確認結果の反映には最大約15秒かかります）。共有リンクを再発行すると新しい募集領域になるため、以前の募集やチャットは新リンクには引き継ぎません。成績の編集権限や公開項目は変わりません。

### アプリのインストール

管理者はaccount.htmlをChromeなどで開き、メニューの「ホーム画面に追加」→「インストール」を選びます。ブラウザが対応していれば、画面内の「アプリをインストール」からも開始できます。iPhoneはSafariの共有メニューから追加します。管理者アプリはマイグループ、募集側のアプリは募集ページから起動します。どちらも通知用のService Workerを登録しますが、成績の保存方法・ログイン情報・入力データを削除・変換しません。

ブラウザとホーム画面アプリの保存領域が異なる場合に備え、募集アプリは初回に共有リンクを貼り付けて卓を開けます。共有リンクがない状態では、未選択の募集一覧の代わりに案内とリンク入力を表示します。


### 共有アプリのグループ名（2026年11月16日）
共有ランキング・募集ページの取得成功後、共有トークンを再検証するサーバーのグループ別マニフェストに切り替える。アプリ名とiPhoneの追加時の名前はグループ名。グループ別の識別IDを持ち、起動先は共有トークン付きランキングURLなので初回も同じ卓の成績を開く。サーバーは公開中の共有トークンだけを許可し、マニフェストは保存キャッシュを禁止する。管理者用account.htmlは従来どおり「卓上反省会」。既存インストールの名前変更は端末によって反映が異なるため、必要なら入れ直す（先に通知をOFFにし、新アプリでONにする）。グループ名が長い場合、端末側で省略表示されることがある。


## 複数人での入力と運営ダッシュボード（2026年11月17日）

- グループ作成者が管理者。管理者は入力・修正、設定、共有の発行・無効化、メンバーの招待・解除が可能。招待で参加したアカウントは入力メンバーになり、対局履歴・進行中セット・プレイヤーを同じグループで入力・修正できる。設定やメンバー権限は変更できない。プレイヤーマスターとログインアカウントは別のもの。
- マイグループには管理者／入力メンバーの役割を表示。管理者は「入力メンバー管理」からメンバーのメールと役割を確認し、招待リンクを作成する。リンクは7日・一回限り、作成ごとに別のリンク。リンクを知る人が参加できるため、招待対象者だけに共有する。送信自体はアプリから行わない。受信者は自分のアカウントにログインし、招待リンクを開き、グループを確認して「参加」を押す。ログインや確認メールで移動した場合は、元の招待リンクを再度開く。URLのフラグメントに秘密を置き、DBには秘密のハッシュだけを保存する。招待URLと成績閲覧URLは別。
- 未使用の招待は一括無効化できる。参加済みの入力権限は個別解除。解除後のサーバー読み書きは拒否し、既存成績は削除しない。既に端末に取得したデータまでは回収できない。
- 成績保存はグループをロックし、入力権限とリビジョンを確認する専用RPCに集約。古いリビジョンでの保存は拒否し、端末の未送信入力と復旧コピーを保つ。同一グループの別のセットを並行入力しても競合するため、その日は一人が入力担当になり、交代時は保存後に開き直す。
- 運営者だけが開けるusage.htmlに全グループ数、グループ別の管理者・入力メンバー・人数（管理者含む）を表示。ユーザー詳細は管理・参加の両方のグループを表示。全体の登録人数はauth.usersのアカウント数なので重複所属でも一人。閲覧だけの人や成績上のプレイヤーは登録ユーザー数に含めない。
- 入力・更新回数は今回以降の正常保存（ワークスペース／プレイヤーマスター）を記録し、同じ保存の再送は二重計上しない。利用ユーザーは期間内に終了対局のある卓の管理者と入力・更新者の和集合（過去の入力者は未記録）。所属卓のセット数・半荘数をユーザー別に表示するため、全ユーザー分の合計は全体件数と一致しない。管理卓数と所属卓数を別に表示する。

### DBへの反映

卓上反省会専用Supabase（aexmoblpehhcqptvagxh）のSQL Editorで `supabase/setup-group-editors.sql` 全文を実行する。既存成績を移行・削除せず、権限テーブルと関数を追加・更新する。繰り返し実行可能。一つのトランザクションで入力機能と運営表示を更新し、成功後にAPIスキーマを再読込する。たけチャートのDBには実行しない。DB未反映時はメンバー画面に設定待ちを表示し、管理者の既存入力・保存は従来方式で継続できる。

### 確認

`npm test` は画面のテストとPGlite上の実PostgreSQLテストを実行する。招待の再利用・失効、別グループの隔離、管理者のみの権限操作、入力メンバーの保存、競合と解除後の拒否、人数の重複防止、初回と再適用の既存データ維持を確認する。本番反映後は別アカウントで招待・入力・解除を確認する。
