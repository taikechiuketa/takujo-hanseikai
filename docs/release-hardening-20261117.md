# 公開前レビューの修正（2026年11月17日）

## 実装と試験

| 指摘 | 対応 | 確認 |
| --- | --- | --- |
| S1 非公開属性を編集者が公開できる | 画面の公開チェックを管理者限定にし、両保存RPC・非公開マーカーをDBでも保護。既存の非公開ID・名前・履歴の差替えを制限 | PostgreSQLで匿名共有の出力まで検証。同名・空白名・削除再追加・設定SQL再実行を含む |
| D1 履歴の退避データを先に削除 | 新内容の永続保護前に元下書きを削除しない。成功後も同内容の下書きだけ削除 | actual UI＋保存処理で容量不足・通信失敗・再起動後の再開を検証 |
| O1 再送で募集・チャット重複 | 固定request_idとD1の同時batchで一件に確定。通知準備の失敗を投稿失敗にしない | 実Workers/D1の同時再送、保存後応答喪失、通知検索失敗、旧クライアントを検証 |
| Q1 自動更新で参加名消失 | 同内容の全面再描画を避け、フォーカス・IME入力・未確定の参加名を保持 | ポーリング・IME・更新後の参加を検証 |
| Q2 遅延応答で次の本文消失 | 送信した内容と一致する場合だけ消去。古いページへの応答を無視 | 応答待ち中の追加入力・画面移動を検証 |
| S2 通知の識別不一致から復旧不能 | 409の専用コードで購読を安全に再発行し、他卓のON状態を再登録 | 解除失敗・同endpoint再発行・他卓復元と所有者の同時競合を検証 |
| S3 招待済みアカウント削除不能 | accepted_byをON DELETE SET NULLへ変更し、使用済み日時を維持 | アカウント削除と使用済み招待の再利用拒否を検証 |
| D2 復旧コピーが無制限 | 1卓12世代、全体80件・16MiB、1件8MiB。各卓の最後のコピーを保持し、上限時は既存維持で停止 | quotaでの追加／削除の原子性、旧IDB移行、起動不能時の書出しを検証 |

追加：募集100件の一覧を201クエリから3クエリへ集約し、room/date/created索引を追加した。依存ライブラリはNext、React/RSC、Vinext、Vite、Cloudflare等を互換確認しながら更新した。Miniflareの新APIには公式変換関数を用い、実Workers/D1の試験内容を維持した。

## DBへの適用

既に入力メンバー用SQLを実行した卓上反省会専用DB（aexmoblpehhcqptvagxh）では、`supabase/release-hardening.sql` の全文をSQL Editorへ貼り付けて実行する。成績の消去・グループの作り直しは不要。再実行できる。新規導入は最新版 `supabase/setup-group-editors.sql` に修正を同梱した。

適用確認用RPC `release_schema_version()` の応答は `2026-11-17.1`。このSQLを本番へ反映するまでS1/S3のサーバー側修正は有効にならない。画面側を更新したことだけで完了と扱わない。非公開プレイヤーを含む履歴の人物ID・名前・公開属性・参加者構成の変更やそのセット削除は管理者が行う。編集メンバーはスコア等の通常修正を継続できる。

通知API側は追加D1マイグレーション0001で既存の募集・投稿・参加を維持する。新APIを先行公開し、その後に固定request_id対応の新しい画面を公開する。

## 公開判定に残るもの

- 本番DBへのSQL反映と、別アカウントによる実際の招待・保存・解除・匿名共有の確認。
- Android/iPhoneの実機でのインストール・グループ名・起動先・バックグラウンド通知・タップ遷移。
- Supabase／D1のバックアップ設定と別環境での復元実績、障害検知、問い合わせ先、削除・退会と保持期間。
- Product checksのCI追加とは別に、必須チェックやPages公開方式の設定を確認する。

実装の修正とローカル試験の合格は、上記の実機・本番運用の確認を代替しない。通常Pushは引き続きbest effortであり、配達保証・永続送信キュー・自動再送は追加していない。

復旧コピーの上限を超える場合は保存を拒否して書出しを案内する。端末内コピーは端末故障・ブラウザデータ削除に対する別媒体バックアップではない。入力メンバーが新規の別名で任意の情報を書くような、意味上の人物同一性までは判定できない。
