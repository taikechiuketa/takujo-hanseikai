# 試作仕様

対局と設定はブラウザ内でグループごとに保存する。初期卓は「おためし卓」。画像と点数表は各10 MBまで。設定と添付はIndexedDBに保存し、対局データは従来のブラウザ保存を使う。点数表は画像またはPDF。ルール本文は閲覧用。クラウド同期と別端末共有は未実装。バックアップは対局データのみ。

画面・仕様変更時は画面説明と仕様書の該当箇所を同じ変更で更新する。

ヘッダー背景色は卓ごとの設定に保存する。未設定時は標準色を使い、文字色は背景の明るさに応じて白または黒を選ぶ。

## 製品版のデータ設計（開発中）

卓上反省会専用のSupabaseを使う。個人用たけチャートのDB、認証、ファイル保存領域、キーは利用しない。

ユーザーはグループを所有し、グループはセットを、セットは半荘を持つ。初期の書き込み権限は作成者のみ。グループ・セット・半荘の参照と変更はDBの行レベル権限で制御する。未ログインのユーザーに開放するテーブルはない。所有者や親への紐付けは作成後にクライアントから変更できない。

新規グループは名前だけで作成し、DBの既定値を使う。既存グループのテンプレート識別子とルール本文は保持し、ルール本文は作成後に編集できる。セット番号は同じグループ・日付の中で一意、半荘番号は同じセット内で一意。グループ削除は配下のセット・半荘も削除するため、削除UIは別途設計する。

スキーマは `supabase/migrations/20261109040000_group_management.sql`。この段階では本番DBに適用していない。ログイン画面、データ移行、公開共有、ファイル保存、課金は後続作業。

開発ブランチのアカウント画面は卓上反省会専用のSupabase Authと `groups` テーブルを使用する。メール確認を有効にする場合はアカウント画面のURLをAuthのリダイレクト許可リストに設定する。接続用の公開キーを使い、データへのアクセスはDBの権限で制御する。

認証クライアントは固定バージョンを同じ配信元から読み込む。

グループ一覧の対局入力は、既存スコアシートのグループモードを開く。専用DBの `20261109042000_sheet_workspace.sql` の適用が必要。グループIDの所有権を確認し、プレイヤーマスター・入力中のセット・セット履歴を取得する。編集はページ内に保持し、明示保存時にセットと半荘を同一トランザクションで書き直す。リビジョン照合により別端末の先行更新の上書きを拒否し、同じリクエストIDの再試行は重複処理しない。共有リンクとクラウド添付はこのモードの対象外。

ログインした卓の選択・作成はグループ一覧で行う。名前・配色・ヘッダー色・ルールは卓のDB設定に保存する。ロゴと点数表はアカウントID・卓IDで分けてIndexedDBに保存する。

対局は `index.html?group=…`、設定は `settings.html?group=…` で提供する。設定ページは認証と対象卓の設定を取得し、対局履歴は取得しない。旧設定リンクは新しい設定ページに転送する。対局画面は登録済みの外観を適用し、ルール・点数表は参照用に表示する。

セット保存・終了でDB保存を開始する。未保存の内容と再送IDは同じアカウント・卓のブラウザに保持し、DBが先行更新された場合は下書きを退避できる。

配色テーマは既存12種に新規8種を追加する。保存済みのテーマ識別子とヘッダー背景色は維持する。

プレイヤーマスターの変更は卓のリビジョンを照合し、マスター列だけを更新する。進行中の対局と履歴はセット保存の操作で確定する。

手動の下書き保存ボタンは置かない。入力途中は端末内の復元用データに保持し、確定操作でDBへ保存する。再試行または下書き退避が必要な状態に限り補助ボタンを表示する。

チップの符号を入力時と再表示時に反映する。保存・終了・新規セット作成時の確認にチップ合計の警告を含める。保存結果は一時通知で表示する。

従来の所有者向け閲覧専用URLは互換性のため残す。成績画面からの導線は卓設定のランキング共有に集約する。閲覧専用モードは所有者認証を使い、保存済みのセットを読み込む。進行中セットと端末の下書きは集計対象外。待機状態は履歴へ表示しない。

グループ削除は所有者のみ。グループIDと確認時の名前が一致する行を削除し、関連するセット・半荘は外部キーで連鎖削除する。

対局画面の初期状態では保存案内を表示しない。下書き復元、保存状況、エラー時は状態に応じて表示する。

マスター更新の応答を取得できないときは、DBのリビジョンを再取得して書き込み結果を確認する。セット保存後はマスターの未保存状態に応じて再試行表示を更新する。

通算成績のJSON出力は画面と同じ集計結果・並び順を使用し、ランキング非表示のプレイヤーを除外する。レーティング画面では出力操作を表示しない。

## セットIDの維持

`20261109043000_stable_set_ids.sql` を適用すると、保存時に既存セットの行を更新し、変更してもセットIDを維持する。既存の `archiveId` を優先して照合し、識別子のない旧バックアップでは日付と伝票番号を使う。削除したセットだけを除去し、半荘は位置ごとに差分を更新する。卓のリビジョン照合とトランザクションは従来どおり。共有リンクは後続対応。

セット共有は `20261109044000_set_sharing.sql` を適用して有効になる。所有者のみ発行・無効化でき、閲覧側にはトークンに対応する1セットの表示用情報だけを返す。安定したセットIDに紐付くため、訂正後も同じURLを使える。

履歴の共有状態は、ログインした所有者が閲覧できる共有行の有無で表示する。取得失敗時は未確認とし、リンク発行・無効化の成功時に表示を更新する。

卓全体のランキング共有は `20261109045000_group_ranking_sharing.sql` を適用して有効になる。個別セット共有と独立し、匿名の取得処理は有効なトークンに対して卓名、選択月、順位、表示名、累計pt、半荘数だけを返す。非表示選手と未確定の入力は対象外。

`20261109050000_protect_sharing_visibility.sql` は、非表示のままマスターから削除された選手の公開除外を保持する。識別子なしで日付と伝票番号を照合したセットは、履歴を更新する同じトランザクションで共有トークンを無効化する。適用以前に削除されたマスターの非表示履歴は復元できない。

スコアシートではセット開始とレートを上部に置き、参加者選択はスコア表の上、半荘追加は表の直下、確定操作は精算欄の下に置く。既存の保存処理・レート値を使う。

対局入力では、半荘追加の下に途中保存、最終精算の下に終了を配置する。最終精算はスコア表と同じプレイヤー順の列を使用し、チップ入力時に入力欄を再生成せず精算額を更新する。

通算成績と個人成績では、ポイント・収支・チップのマイナス値を赤字で表示する。

セット履歴の共有操作は編集・削除と同じ行に配置する。共有リンクの取得と再コピーは鎖アイコン付きボタンで表示する。

セット共有ページは、保存時のポイント倍率・チップレート、プレイヤー別のポイント・チップ・精算額、半荘別スコアを表示する。精算額はポイント×倍率＋チップ×レート。精算額の表示には `20261109163000_shared_set_settlement.sql` の適用が必要。
